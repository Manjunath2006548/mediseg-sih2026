\section{Problem Statement}

\textbf{Organiser:} Autodesk \textperiodcentered\ \textbf{Hackathon:} Smart
India Hackathon (SIH) 2026.

The problem statement asks teams to design a
\textit{``Smart Mobile Medical-Waste Collection and Segregation System''}.
Hospital biomedical waste is hazardous to handle, is frequently mis-segregated,
and exposes healthcare workers to pathogens and sharps. A compliant system must
automate collection, sort waste into the legal categories, and keep a traceable
record end to end.

\subsection{Delivered approach}
MediSeg replaces the manual pushcart with an \textbf{autonomous mobile rover} that:
\begin{enumerate}[leftmargin=1.6em, itemsep=2pt]
  \item navigates hospital areas autonomously (LiDAR/SLAM-style patrol),
  \item recognises waste bags with an AI vision model (simulated YOLOv8, $98\,\%$),
  \item drops each bag into the correct BMWM 2018 colour-coded compartment, and
  \item records a QR-style chain of custody for regulatory compliance.
\end{enumerate}

\section{Project Journey (Beginning to End)}

The following timeline reflects the actual order in which the work was done.

\begin{enumerate}[leftmargin=1.6em, itemsep=4pt]
  \item \textbf{Project origin.} Work started inside an existing Next.js~14
        (App Router) frontend that had previously been used for another SIH
        problem (an ISRO component-screening demo). A new section
        \texttt{app/mediseg/*} was added so the new solution could be built
        without disturbing the older pages.

  \item \textbf{Concept deck first.} The first page created was the
        presentation/concept deck at \texttt{/mediseg/presentation} to define
        the problem, solution, design, impact, and roadmap.

  \item \textbf{Interactive prototype.} The core deliverable, an interactive
        autonomous-rover simulator, was built at \texttt{/mediseg}. It grew
        into four linked panels (Robot View, AI Scanner, Segregation,
        Tracking) plus login-gating.

  \item \textbf{Local hosting and verification.} The static build was served on
        \texttt{127.0.0.1:8000} with a Python HTTP server so the prototype
        could be demonstrated locally; every route was verified with HTTP
        checks.

  \item \textbf{Camera idle-state fix.} The scanner's empty state was improved
        to show ``Camera Live --- Awaiting Waste Intake'' with an inline
        \emph{Generate Waste Now} action instead of a blank viewport.

  \item \textbf{Introduction page.} A landing page at \texttt{/mediseg/intro}
        was added (hero, capability cards, workflow steps, statistics, CTA).

  \item \textbf{Login/register page.} A portal at \texttt{/mediseg/login} was
        added with Sign In / Register tabs. One-click demo account buttons were
        introduced and then \textbf{removed} on request so every user goes
        through the normal form.

  \item \textbf{Themed background.} A custom SVG background
        (\texttt{mediseg-bg.svg}) was designed and applied to every page of the
        solution for a consistent medical-tech look.

  \item \textbf{Strong-password validation.} The Register flow gained a
        five-rule strength checker with a live meter, required for account
        creation.

  \item \textbf{First deployment.} The combined Next.js app (ISRO pages +
        MediSeg) was pushed to GitHub and deployed to Vercel
        (\texttt{isro-burnin-detection.vercel.app}).

  \item \textbf{Standalone repository.} On request, MediSeg was extracted into
        its own repository (\texttt{mediseg-sih2026}) containing only the
        MediSeg pages, its own portal home page, README, and background, and
        deployed to its own Vercel project
        (\texttt{mediseg-sih2026.vercel.app}).

  \item \textbf{All-in-one portal.} The new home page presented the project
        overview plus cards linking to every part of the demo.

  \item \textbf{Git contribution setup.} Commit authorship across the Git
        history was rewritten to the owner's GitHub identity (real verified
        email) so the contribution graph reflects the work. Local Git
        configuration was updated to carry the same identity.

  \item \textbf{LaTeX user guide.} A complete user guide was written in
        \LaTeX~(\texttt{docs/UserGuide.tex}) and committed with the README.

  \item \textbf{Login-gated launch.} The portal was revised: the Introduction
        card, the ``Launch Simulation'' button, and the direct prototype card
        were removed. Users must now sign in before they can operate the
        prototype (it is protected by an access gate).
\end{enumerate}

\section{Authentication \texttt{/mediseg/login}}

\begin{warnbox}
This page performs a \textbf{client-side simulation} of authentication for the
demonstration. No password is ever transmitted or stored; nothing is written to
any server. Do not reuse real credentials here, and never expose them in
reports or documentation.
\end{warnbox}

\subsection{Mode tabs}
Two tabs: \textbf{Sign In} and \textbf{Register}.

\subsection{Registration (Register tab)}
Fields and validation:
\begin{itemize}[leftmargin=1.6em, itemsep=2pt]
  \item \textbf{Full name} -- required (non-empty).
  \item \textbf{Email} -- required, validated with a standard
        \texttt{user@domain.tld} regular expression.
  \item \textbf{Password} -- live strength checker with five rules:
\end{itemize}
\begin{enumerate}[leftmargin=1.6em, itemsep=2pt]
  \item at least 8 characters,
  \item at least one uppercase letter (A--Z),
  \item at least one lowercase letter (a--z),
  \item at least one digit (0--9),
  \item at least one special character (\texttt{! @ \# \$ \%} and similar).
\end{enumerate}
\begin{itemize}[leftmargin=1.6em, itemsep=2pt]
  \item A \textbf{password strength meter} with 5 segments and three levels:
        Weak ($\leq$ 2 rules), Medium (3--4 rules), Strong (5 rules).
  \item A live \textbf{checklist} of the five rules with check/empty indicators.
  \item Registration is \textbf{rejected} if fewer than 4 of the 5 rules pass.
  \item Optional \textbf{Role} selector: Facility Manager / Admin, Rover
        Operator, QA / Compliance Officer.
  \item Show/hide password toggle (\texttt{SHOW}/\texttt{HIDE}).
  \item On success the session is stored in \texttt{localStorage}
        (key \texttt{mediseg\_user}, value \{\texttt{name}, \texttt{email},
        \texttt{role}\}), a confirmation is shown, and the page switches to
        Sign In.
\end{itemize}

\subsection{Sign in (Sign In tab)}
\begin{itemize}[leftmargin=1.6em, itemsep=2pt]
  \item Email and password are required; a meaningful message is shown if
        missing.
  \item The display name is derived from the email prefix (capitalised).
  \item The session is stored in \texttt{localStorage} under
        \texttt{mediseg\_user} and the user is redirected to the prototype
        \texttt{/mediseg}.
\end{itemize}

\subsection{Footer links}
\texttt{$\leftarrow$ Back to Intro} and \texttt{Concept Deck $\rightarrow$}.

\section{Session Handling \& Access Control}

\begin{itemize}[leftmargin=1.6em, itemsep=2pt]
  \item \textbf{Storage:} the session object \{\texttt{name}, \texttt{email},
        \texttt{role}\} is kept in \texttt{localStorage['mediseg\_user']}.
  \item \textbf{Persistence:} sessions survive page reloads within the browser.
  \item \textbf{Prototype gate:} on load the prototype reads the stored user.
        While access is being checked it shows a ``Verifying access\ldots''
        spinner. If no user is found it renders an
        \textbf{``Access Restricted''} screen with a \textbf{Sign In to
        Continue} button that navigates to \texttt{/mediseg/login}.
  \item \textbf{Logout:} clears the storage key and returns to
        \texttt{/mediseg/login}.
  \item The prototype header shows the signed-in user's avatar initial and name.
\end{itemize}

      \item No Manual Contact (zero-touch handling),
      \item Decontamination (HEPA airflow + UV cycle).
    \end{enumerate}
\end{itemize}

\subsection{Micro-behaviours worth noting}
\begin{itemize}[leftmargin=1.6em, itemsep=2pt]
  \item Battery drains $0.02 \times \text{speed}$ per patrol step (floor 10\,\%)
        and drops $0.2$--$0.6$ on danger alerts (floor 12\,\%).
  \item Auto-collect scans every $2200\,ms \div \text{speed}$.
  \item Ledger entry fields: id, item, type, typeName, binId, binName, weight,
        time, source (current map node), operator
        ``Autonomous Rover MS-01''.
  \item Live accuracy $=$ accurate $\div$ classified; capacity $=$
        litres $\div$ 60\,L.
\end{itemize}
