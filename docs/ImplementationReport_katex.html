1. Scope of This Report

This report records everything implemented for the MediSeg solution, in the order it was built. It covers the project journey, architecture, every page and feature, the simulator data model, authentication and access control, hosting and deployment, Git history, and build commands.

Security & Credentials Policy. No credentials, login account names, or example passwords are published in this report or the repository. MediSeg is a client-side prototype: authentication is simulated in the browser and no secret material exists in the codebase.

2. Problem Statement

AutodeskSIH 2026 Problem: design a Smart Mobile Medical-Waste Collection and Segregation System. Hospital biomedical waste is hazardous, frequently mis-segregated, and exposes workers to pathogens and sharps; the solution must automate collection, sort waste into legal categories, and trace every batch.

Delivered approach

  1. an autonomous mobile rover navigates hospital areas (LiDAR/SLAM-style patrol),
  2. an AI vision model recognises waste bags (simulated YOLOv8, \(98\,\%\) accuracy),
  3. each bag drops into the correct BMWM 2018 colour-coded compartment, and
  4. a QR-style chain of custody keeps a regulatory record.

3. Project Journey (Beginning to End)

  1. Project origin. Work started inside an existing Next.js 14 (App Router) frontend previously used for another SIH problem (an ISRO component-screening demo). A new app/mediseg/* section was added without disturbing the older pages.
  2. Concept deck first. The first page was the presentation / concept deck at /mediseg/presentation.
  3. Interactive prototype. The core autonomous-rover simulator was built at /mediseg — four panels (Robot View, AI Scanner, Segregation, Tracking) plus login-gating.
  4. Local hosting. The static build was served on 127.0.0.1:8000 for local demonstration; every route was verified.
  5. Camera idle-state fix. Empty scanner now shows “Camera Live — Awaiting Waste Intake” with a Generate Waste Now action.
  6. Introduction page at /mediseg/intro (hero, capability cards, workflow, statistics, CTA).
  7. Login/register page at /mediseg/login. One-click demo account buttons were introduced and then removed on request so every user uses the real form.
  8. Themed background. Custom mediseg-bg.svg applied to every page.
  9. Strong-password validation with a five-rule strength checker added to registration.
  10. First deployment. Combined app deployed to Vercel (isro-burnin-detection.vercel.app).
  11. Standalone repository. MediSeg extracted into mediseg-sih2026 with its own portal, README, and background, deployed to mediseg-sih2026.vercel.app.
  12. All-in-one portal. New home page with overview + cards to every part of the demo.
  13. Git contribution setup. Commit authorship rewritten to the owner’s GitHub identity (verified email) so the contribution graph reflects the work; local Git config updated accordingly.
  14. LaTeX user guide. docs/UserGuide.tex added.
  15. Login-gated launch. Portal revised: the Introduction card, “Launch Simulation” button, and direct prototype card were removed. Users must sign in before operating the prototype.

8. Authentication /mediseg/login

This page performs a client-side simulation of authentication. No password is transmitted or stored; nothing is sent to any server. Do not reuse real credentials here, and never include credentials in reports or docs.

Register

  • Full name — required.
  • Email — required, validated with a user@domain.tld regex.
  • Password — live strength checker, five rules:
  1. at least 8 characters,
  2. at least one uppercase letter (A–Z),
  3. at least one lowercase letter (a–z),
  4. at least one digit (0–9),
  5. at least one special character.
  • Strength meter with 5 segments: Weak (\(\le 2\) rules), Medium (\(3\)–\(4\)), Strong (\(5\)).
  • Live checklist of the five rules.
  • Registration rejected if fewer than 4 of 5 rules pass.
  • Optional Role: Facility Manager / Admin, Rover Operator, QA / Compliance Officer.
  • Show/hide password toggle.
  • On success the session is stored in localStorage['mediseg_user'] and the page switches to Sign In.

Sign In

  • Email and password required; friendly message if missing.
  • Display name derived from the email prefix (capitalised).
  • Session stored; redirect to the prototype /mediseg.

9. Session Handling & Access Control

  • Storage: session object {name, email, role} in localStorage['mediseg_user'].
  • Persistence: survives page reloads in the browser.
  • Prototype gate: if no stored user — “Access Restricted” screen with Sign In to Continue button.
  • Logout: clears the key and returns to /mediseg/login.
  • The prototype header shows the signed-in user's avatar initial and name.

10.4 Top bar

Rover identity “MEDISEG · Autonomous Rover MS-01” with ONLINE badge; WiFi indicator; battery (starts at \(94\,\%\)); View Concept Deck link; signed-in user chip; Logout; Home.

10.5 Alert flash bar

Success (emerald), danger (red), info (blue). Danger alerts drain a little battery.

10.6 Sidebar

Tabs: Robot View, AI Scanner, Segregation, Tracking. Live stats: items, weight, AI accuracy, capacity. Controls: Generate Waste, Auto-Collect toggle, speed slider (\(0.5\times\)–\(3\times\), steps of \(0.5\)); sensor list: Obstacle Sensor OK, LiDAR Mapping Active, Airborne HEPA Filter.

10.7 Robot View

  • Telemetry: Current Location, Waste Compartments (active/5), Total Load (kg), Collection Trips.
  • SVG floor plan: grid, corridors, 8 nodes, animated rover ROV-MS1 with blinking beacon; position step every \(1400\ \mathrm{ms}/\text{speed}\); one full lap → +1 trip. Start / Pause Route, Recharge (\(+40\,\%\), capped at \(100\,\%\)).
  • Compartment live fill: five mini meters with item counts.

10.8 AI Scanner

  • Badges: AI Vision Classifier, “YOLOv8 · Object detection → CNN classification”, INTEGRITY \(98\,\%\).
  • Camera viewport states:
    1. Idle: “Camera Live — Awaiting Waste Intake” + Generate Waste Now;
    2. Detect: pulsing scan frame with corner brackets + spinner;
    3. Classify: confidence bars for all five categories;
    4. Segregate: routing animation to the target compartment.
  • Pipeline timing: detect at \(0\ \mathrm{ms}\), classify at \(600\ \mathrm{ms}\), segregate at \(1300\ \mathrm{ms}\), complete at \(2100\ \mathrm{ms}\) — all scaled by speed.
  • Credibility model: confidence \(\sim \mathcal{U}(0.92, 0.985)\); \(2\,\%\) misclassification probability routes to the yellow (infectious) bin — this powers the live accuracy metric.
  • Waste catalogue: 15 item buttons (label, colour dot, weight) triggering a manual scan.
  • Model output — traceability card: latest record's Batch ID, Source, Operator, destination compartment, timestamp.

10.9 Segregation

  • “5 color-coded compartments per BMWM Rules 2018”; total capacity bar \(k/60\ \mathrm{L}\).
  • Per-compartment card: colour accent, emoji, name, litres used, animated fill bar, item/weight counters, remaining litres, “Disposer Ready”, pulsing NEAR FULL above \(80\,\%\).
  • Robotic Dispenser: rotating-carousel zero-contact routing with five colour chips.

10.10 Tracking

  • Stat cards: Items Collected, Total Weight, AI Accuracy, Compliance Logs.
  • End-to-end traceability ledger: Batch ID, Item, Classified, Compartment, Weight, Source, Operator, Time; empty state prompts the user to scan.
  • Compliance report (BMWM Rules 2018), six checks with \(\checkmark/\circ\): Segregation at Source (AI-verified), Colour-Coded Bags, Digital Manifest (CPCB-ready), Tracking to Treatment, No Manual Contact, Decontamination (HEPA airflow + UV cycle).

10.11 Micro-behaviours

  • Battery drains \(0.02\times\text{speed}\) per patrol step (floor \(10\,\%\)); danger alerts drop \(0.2\)–\(0.6\) (floor \(12\,\%\)).
  • Auto-collect scans every \(2200\ \mathrm{ms}/\text{speed}\).
  • Ledger fields: id, item, type, typeName, binId, binName, weight, time, source (current map node), operator “Autonomous Rover MS-01”.
  • Accuracy \(=\ \text{accurate}/\text{classified}\); capacity \(=\ \text{litres}/60\ \mathrm{L}\).
